Architecture Quant Trading — Sentiment + TCG + XGBoost
Résumé de conversation — Mai 2026

1. OBJECTIF
Construire un modèle de trading quantitatif hybride combinant :

Features de sentiment sur les news économiques
Graphe causal temporel (TCG) avec decay
Détection de régime de marché
XGBoost par régime comme modèle de décision final


2. GRAPH RAG CAUSAL — PRINCIPE
Concept
Associer des entités (Trump, COVID, Fed...) à des impacts marchés historiques,
et propager ces associations par analogie structurelle.
Exemple :

COVID → sell-off SPX -34%
H5N1 est_similaire_à COVID × 0.71
→ H5N1 détecté → signal baisse modulé par similarité

Structure du graphe

Nœuds : acteurs, concepts, assets, événements
Arêtes : relations causales pondérées + datées
Poids : base_weight × decay(t) × condition_score

Analogie structurelle
score = 0.4 × similarité_ontologique
+ 0.4 × similarité_embedding
+ 0.2 × similarité_contextuelle

3. TEMPORAL CAUSAL GRAPH (TCG)
Principe du decay
Les relations causales s'affaiblissent dans le temps sans rappel similaire.
weight(t) = base_weight × exp(-ln(2) × dt / half_life)
Reinforcement
Quand un événement similaire arrive, l'arête est réactivée :
new_weight = weight_decayed + similarity × 0.3
Régime de marché conditionne le decay
RégimeVIXHalf-lifeComportementBull< 1560jOubli rapideTransition15-30180jInstableBear> 30365jMémoire longueCrisis> 50730jCicatrice durable
Même relation COVID→crash :

Régime bull  (2021) : weight = 0.001 (quasi morte)
Régime bear  (2022) : weight = 0.24  (encore active)
Régime crise        : weight = 0.48  (bien présente)

Feedback loop
VIX monte → decay ralentit → algos réagissent plus fort → VIX monte encore

4. ARCHITECTURES ALTERNATIVES
1. Temporal Causal Graph (TCG) — recommandé

Causalité Pearl (do-calculus) avec DoWhy
Distingue corrélation vs causalité
Permet raisonnement conditionnel ("sans lockdown → quel impact ?")

2. Event-Driven SSM (Mamba-style)

Marché = état continu perturbé par événements discrets
Apprend les poids end-to-end
~5ms latence

3. LLM World Model

Fine-tuning sur historique news + returns
Outputs probabilistes (distributions, pas points estimates)
Excellent pour black swans
~800ms latence → stack "System 2"

Architecture cible

Événement connu + rapide  → TCG (causalité explicite)
Signal continu temps réel → SSM (performance pure)
Événement rare / ambigu   → World Model (raisonnement)

8. MODÈLE DE DÉCISION
Architecture : XGBoost par régime

1 modèle entraîné sur périodes bull
1 modèle entraîné sur périodes transition
1 modèle entraîné sur périodes bear/crisis
Router = régime_detector → active le bon modèle

Paramètres anti-overfit

max_depth        = 3
n_estimators     = 100
learning_rate    = 0.05
min_child_weight = 50
subsample        = 0.8

Validation walk-forward strict

Expanding window (jamais full history)
Half-lives calibrées sur passé uniquement
IS Sharpe vs OOS Sharpe : ratio < 2x sinon overfit
